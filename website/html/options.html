Options

What to run, what to run it in, how much of it to run at once, and what to print. The same names are options of App::Actions->new, so a Perl program can pass any of them directly.

Jobs and images

OptionEffect
--job NAME
also -j		 Only run jobs whose id or expanded display name matches. Repeatable.
--image IMAGE Fallback image for Linux jobs that declare no container: and do not use shogo82148/actions-setup-perl. Default ubuntu:latest; a job with runs-on: ubuntu-24.04 changes the default to ubuntu:24.04.
--perl-image TEMPLATE Image template used for shogo82148/actions-setup-perl. Default perl:%s, so perl-version: "5.38" uses perl:5.38.
--platform PLATFORM Pass --platform to Docker, for example linux/amd64 on an ARM computer.
--docker PROGRAM The Docker program to run — a path, or a wrapper script. A wrapper written in Perl runs with the same Perl as action-run, so it works on Windows too. Default $DOCKER, then docker.
--user USER[:GROUP] Run the job and service containers as this user. By default they run as the image's default user, usually root. If the user is neither you nor root, the job's runner folder must be readable by every user, and a warning says so.
--env NAME=VALUE Add or override an environment variable. Repeatable.
--secret NAME=VALUE Make a value available to ${{ secrets.NAME }}. Repeatable. Values are redacted from printed Docker commands and never put on a Docker command line.

What the run does

OptionEffect
--pull, --no-pull Force an image pull, or fail instead of pulling a missing image. With --pull each image is pulled once per run, however many jobs, services or steps use it.
--dry-run
also -n		 Print the Docker commands and run scripts without starting containers.
--explain A dry run for containers rather than commands: starts nothing, needs no daemon, and prints one block per container saying what it would be told to run. Only a run has containers to explain, so the other commands reject it.
--list List the expanded jobs and exit.
--keep
also -k		 Keep containers, networks, images and the temporary directory for debugging. A run that keeps its containers always goes one job at a time.
--keep-images, --no-keep-images Keep the images the run pulled, so the next run starts from them. This is the default. --no-keep-images removes the ones this run pulled once its containers and networks are gone.
--strict-actions Treat unsupported actions as failures instead of skipping them with a warning.
--skip-check Skip the environment probes and the up-front image preparation, while still checking that the Docker command answers. Images are then pulled when first used.
--older-than DURATION With cache or logs: show only entries at least this old, and make --prune remove only those. A duration is a number and a unit — 30s, 15m, 12h, 7d, 2w, 3mo, 1y — with the unit optionally spelled out. The unit is required.
--prune With cache, remove the images the record holds; with logs, remove the kept job logs. Rejected by every other command.

Concurrency and output

OptionEffect
--parallel NUMBER, --parallel=off How many jobs of a matrix may run at once. Default: the number of processors, so a matrix uses the machine. off runs them one at a time, for jobs that compete for a fixed port or a shared service. The workflow's own strategy.max-parallel still caps the number. A kept run, a dry run and an explain run always go one at a time, and so does Windows, where fork() is not reliable.
--pull-concurrency NUMBER How many images may be pulled at the same time. Default: ACTION_RUN_PULL_CONCURRENCY, then four. 1 pulls them one after another, which is easier to read when one is slow. Must be a positive integer. Windows always pulls one at a time.
--json With check, preflight, cache or logs: print a versioned document instead of the text report. Rejected for a workflow run and unnecessary for schema.
--verbose
also -v		 Print Docker commands and extra diagnostics.
--quiet
also -q		 Suppress progress output. Command output is still shown, and the job logs are still kept.
--help, --version Show the help or the version and exit 0.

Environment variables

VariableMeaning
ACTION_RUN_LANG Language of the messages: en (default), fr, de or zh. The system locale is not consulted, so a script on a CI machine always sees English unless it asks.
DOCKER The Docker program, when --docker is not given.
ACTION_RUN_PULL_CONCURRENCY The default for --pull-concurrency. The option wins, and this wins over the built-in four.
ACTION_RUN_LOG_DIR Where parallel runs keep their per-job logs, and where action-run logs reads them. Default $XDG_CACHE_HOME/action-run/logs, or ~/.cache/action-run/logs; %LOCALAPPDATA%\action-run\logs on Windows.
ACTION_RUN_CACHE_FILE Where the image cache record lives. Default $XDG_CACHE_HOME/action-run/cache.json, or ~/.cache/action-run/cache.json; %LOCALAPPDATA%\action-run\cache.json on Windows. Set it to keep one project's images out of the machine-wide record.
App__Actions__OPTION Sets one of the run options, for example App__Actions__parallel=2 or App__Actions__keep_images=0. It wins over the command line and over the configuration files, and its value is not checked.
CONFIG_DIR The directory searched for configuration files. Default ~/.conf, ~/config, ~/conf, then conf.

Configuration files

Object::Configure looks for files named base.yaml and then local.yaml (or .json, .xml, .ini and so on) in the directory CONFIG_DIR names, or in those default directories. Settings for this tool go in an App__Actions section: 

# ~/.conf/local.yaml
---
App__Actions:
  parallel: 2
  keep_images: 0

That is convenient on a computer where every run should use two job slots, and surprising on the day you forget it exists. A logger may be set there too, and a UNIVERSAL section of universal.yaml applies to every class that uses Object::Configure, this one included.

Precedence is the reverse of what you may expect

From weakest to strongest: the arguments, then the configuration files, then the App__Actions__* environment variables. If ~/.conf/local.yaml says parallel: 8, then parallel => 2 and --parallel=2 still run eight jobs at a time. When an option seems to be ignored, look there (env | grep App__Actions). Values from those places are not validated, so a nonsense value is not reported as an argument would be.

As a Perl API

use App::Actions;

my $actions = App::Actions->new(
        workflow_file => '.github/workflows/ci.yml',
        jobs          => [ 'test' ],
        secrets       => { CODECOV_TOKEN => $ENV{CODECOV_TOKEN} },
        parallel      => 4,
);

exit $actions->run;   # 0, 1 or 2

run, preflight and list_jobs accept any of the run options as per-call overrides. logger chooses where warnings and errors go: a Log::Abstraction object, an array reference to collect them in, a hash of logger options, or the string 'NULL' to discard them. Progress, Docker command echoes and the job summary are output, not diagnostics, and stay on standard output.
