Commands

One program, action-run. With a workflow file it runs the workflow; with a subcommand it checks the host, prepares images, or inspects and validates what earlier runs kept. 

action-run [options] <workflow.yml> [project-directory]
action-run [options] check [directory]
action-run [options] preflight <workflow.yml> [project-directory]
action-run [options] schema <check|preflight|cache|logs>
action-run [options] validate <check|preflight|cache|logs> <document.json>
action-run [options] cache [--prune] [--older-than DURATION] [--json]
action-run [options] logs  [--prune] [--older-than DURATION] [--json]

run

default

Reads the workflow and executes its Linux jobs in Docker. Each job gets a private network, its service containers and one long-lived container; the steps run in that container with docker exec, so files and installed modules persist between them. Containers and networks are removed when the job finishes.

Before anything starts, the same probes as check run, and the images of the selected jobs, their services and their docker:// actions are prepared — pull_concurrency at a time, four by default. A failed step fails the job; the jobs of a matrix run in parallel up to --parallel (one per processor by default). 

action-run ~/src/njh/CGI-Info/.github/workflows/perl-ci.yml \
           ~/src/njh/CGI-Info

action-run --job test --image perl:5.40 .github/workflows/test.yml .

action-run --dry-run --verbose .github/workflows/alpine.yml .

check

host probe

Reports the platform, whether the Docker daemon is reachable and can run Linux containers, and whether Docker can bind-mount the host directories a run needs. The mount probe starts one short-lived container using --image and reads a file back from a temporary directory. The directory given as an argument — the current directory by default — is mounted read-only as well, and the entries visible inside the container are compared with the host, which catches a drive Docker Desktop has not shared.

Each problem is followed by the step that fixes it, and the command exits 0 when the environment is ready and 2 when a problem was found. 

  problem   the daemon is not reachable; is Docker running and can this user access it?
  remedy    start Docker Desktop and wait until it is running, then try again
  remedy    if the engine will not start, run "wsl --shutdown" and start Docker Desktop again

--json prints a single versioned document instead of the text report, for a CI job to assert on. See JSON & CI.

preflight

checks + images

Runs the checks a normal run makes before its first job and stops there: the environment probes, then the preparation of every image the selected jobs need. Nothing is started, so this is the cheap way to ask whether a workflow could start on this host.

The text output is the check report, the pull progress, and one line per image naming the job, service or action that needs it and whether it was pulled, already present, failed, skipped or deferred. A deferred image is one whose name only a step can supply: it is printed by its expression, and the step prepares it when the workflow runs. It ends with a schema line naming the version of the preflight document.

It exits 0 when the images are ready and 2 when they are not. Unlike a run, it keeps the images it pulled, so a run that follows starts warm. 

action-run preflight .github/workflows/ci.yml .
action-run preflight --json .github/workflows/ci.yml . > preflight.json

schema

contract

Prints the JSON schema of the named document — check, preflight, cache or logs — and exits. The schema and the version it declares come from the module that produces the document, so the two cannot disagree. It always prints JSON, so --json is rejected. 

action-run schema preflight > preflight-schema.json
action-run preflight --json .github/workflows/test.yml . \
    | check-jsonschema --schemafile preflight-schema.json -

validate

without Docker

Checks a saved document against the schema action-run schema prints, without Docker and without a workflow. The document name is required because a document says which shape its schema_version refers to, but not which command produced it. 

action-run validate preflight preflight.json
'preflight.json' is a valid preflight document (schema version 3)

A document that does not match prints the first mismatch and how many others there are, then exits 70. A file that is not JSON is rejected the same way; an unknown document name or an unreadable file is a usage error and exits 2.

cache

images kept

Lists the images that runs have kept, with the size each one takes and when a run last used it. This is about the daemon's images rather than a workflow, so it takes no workflow file and no project directory. A name is removed from the record only when the image is gone or was removed by --prune, so an image deleted outside action-run is shown as missing rather than silently forgotten. 

Cache file: /home/me/.cache/action-run/cache.json

  IMAGE                                  SIZE  LAST USED          AGE
  alpine:3.20                         11.8 MB  2026-10-21 15:04  2 minutes ago
  perl:5.38                          157.2 MB  2026-10-21 15:04  2 minutes ago

2 images, 169.0 MB on disk.

Listing works with the daemon switched off: the names and dates are still printed and the sizes are reported as unknown. --prune needs the daemon, because it has to know what is still there; an image it cannot remove stays in the record and makes the command exit 1. An unreachable daemon exits 2 without touching the record. 

action-run cache --older-than 30d
action-run cache --prune --older-than 7d
action-run cache --json | jq -r '.totals.size'

logs

job output kept

Lists the per-job logs that parallel runs kept, with the size each one takes and how long ago the run wrote it. A sequential run has no interleaved output to untangle and keeps no copies, so only parallel runs appear. The age is the file's own modification time. 

Logs directory: /home/me/.cache/action-run/logs

  RUN                               LOG                          SIZE  AGE
  20261021-121355-6ad8e4c30f83      job-1-test_n_one.log        1.2 KB  2 hours ago
  20261021-121355-6ad8e4c30f83      job-2-test_n_two.log        0.8 KB  2 hours ago
  20261020-091201-1f4b2c3d4e5f      job-1-test_n_one.log        1.0 KB  1 day ago

3 logs, 3.0 KB on disk.

--prune removes every selected log and the run directory once that is empty. Only a file that matched the listing is unlinked, so a note left in a run directory survives, and only a directory named the way action-run writes one is considered. A removal that fails is reported, the rest of the prune carries on, and the command exits 1. 

action-run logs --older-than 30d
action-run logs --prune --older-than 7d

--list

nothing runs

Prints one line per expanded job — its id, a tab, and its display name — and exits 0. With --job it lists only the jobs that filter selects.

action-run-smoke

second program

The end-to-end check to run after installing, or after changing Docker, a virtual machine or a drive's sharing settings. It does what check does and then runs a small workflow against the real daemon: four steps in one container, proving that a variable written to GITHUB_ENV and an output written to GITHUB_OUTPUT by one step are seen by the next, and that the container is Linux. It needs no prove and reports the environment before it runs anything. 

action-run-smoke
action-run-smoke --directory ~/src --verbose
action-run-smoke --platform linux/amd64
action-run-smoke --scenario deferred

Exit status

StatusMeaning
0Every runnable job succeeded; check found the environment ready; a prune removed everything it selected.
1A job failed, or a prune could not remove an entry (it stays in the record).
2A usage, Docker or infrastructure error: an unknown option, an unreachable daemon, an image that cannot be pulled, a missing workflow.
70A JSON document did not match the schema it is checked against. It is EX_SOFTWARE: the document is at fault, not the host. Please report it.
