Install

App::Actions is a Perl distribution. It installs one module tree and two commands, action-run and action-run-smoke, and it needs a Docker daemon that can run Linux containers.

From CPAN

cpanm App::Actions

That pulls in everything the module needs, including YAML::PP, Object::Configure, Log::Abstraction and Params::Validate::Strict.

From a checkout

git clone https://github.com/nigelhorne/App-Actions.git
cd App-Actions
perl Makefile.PL
make
make test
make install

The test suite runs against a fake Docker command, so make test needs neither Docker nor a daemon. prove -l t runs the same suite from the checkout without installing.

No Docker for the tests

The tests that need a real daemon are opt-in: make test LIVE_TESTING=1. t/self_test.t runs the command a user runs, bin/action-run t/lib/self_test.yml ., in a real container rather than the fake one.

Requirements

NeedsWhy
Perl 5.14 or later What the distribution declares. Continuous integration runs the suite on Perl 5.36 and later.
Docker, running Linux containers Every job, its services and its docker:// actions are containers. Windows and macOS hosts work; only the containers are Linux.
A reachable daemon that can bind-mount your project The project directory is mounted into the job container. On Docker Desktop the drive holding the project must be shared.
Disk space for images Images are kept between runs as a cache. action-run cache shows what they take.
node, only for JavaScript actions A local JavaScript action is run inside the job image, so that image needs a node.

Docker, on each platform

Linux

Install Docker Engine from your distribution, start it, and make sure your user may talk to the socket — usually by being in the docker group. Then run action-run check.

macOS and Windows

Install Docker Desktop and wait until it says it is running. On Windows, the engine must be in Linux-container mode (Docker Desktop's default); on Windows the per-job logs and the image cache live under %LOCALAPPDATA%. Ensure the drive that holds your project is shared with Docker, or the bind-mount probe in action-run check will report the entries it could not see.

Prove it with the smoke test

After installing, or after changing Docker, a virtual machine or a drive's sharing settings, run action-run-smoke. It checks the environment and then runs a small workflow against the real daemon. If it says ready and the workflow passes, action-run will work on this computer.

Verify the install

action-run --version
action-run 0.002.1

action-run check ~/src/my-project
host      Linux (linux), perl 5.40.0, x86_64-linux
...
schema    version 2 (action-run schema check)
Result: ready

action-run-smoke

check says nothing but its report, and ends with Result: ready when everything it tested works. Each problem it finds is followed by a remedy line naming the step that fixes it, and the command exits 2. If action-run is not on your PATH, find where the scripts went with perl -V:installscript.
