Quick start

Five minutes from a workflow file to a passing local run. The project directory is optional when the workflow sits inside .github/workflows — the repository root is found from there.

1. Check the host

action-run check ~/src/my-project

This reports the platform, the Docker client and daemon versions, whether the daemon runs Linux containers, and whether Docker can bind-mount a temporary directory and your project. It is silent when everything works and prints the full report, with a remedy after each problem, when it does not. Fix those first; nothing else will work until it says Result: ready.

2. See what would run

action-run --list .github/workflows/ci.yml

One line per expanded job: its id, a tab, and its display name. A matrix appears as one line per entry, so this is also the quickest way to see whether a matrix is written the way you think it is. 

test	test (perl=5.38)
test	test (perl=5.40)

3. Look before you run

action-run --dry-run --verbose .github/workflows/ci.yml .

A dry run prints the Docker commands and the step scripts without starting anything. --explain is the other half of the idea: it prints one block per container the workflow would start, saying what each one would be told to run, without contacting the daemon at all. That is how a service that stops on start-up is told apart from one that was given a bad command.

4. Run it

action-run .github/workflows/ci.yml .

The exit status is the answer: 0 when every runnable job passed, 1 when a job failed, 2 for a usage, Docker or other infrastructure error. A failed job does not die — the status says so.

5. One job, one secret, one image

action-run --job test \
           --secret CODECOV_TOKEN="$CODECOV_TOKEN" \
           --image perl:5.40 \
           .github/workflows/ci.yml .

--job may be repeated, and matches either a job's id or its expanded display name. --env NAME=VALUE adds an environment variable and --secret NAME=VALUE makes a value available to ${{ secrets.NAME }}; both are repeatable. Nothing is read from GitHub, so a secret that is not passed in is empty, as it is on GitHub for a fork.

Secrets are on your command line

--secret and --env values are visible to other users of the computer while action-run runs. The Docker commands it prints have them redacted, and they never appear in a container's arguments. On a shared machine, pass a test value.

6. Read the output, then the logs

A matrix runs one job per processor by default. Each job's output is streamed as it is written and prefixed with the job it came from, so two jobs working at once can be told apart. Each job's full log is copied out of the temporary directory before the run removes it, and the run ends by saying where the copies are. 

action-run logs

Logs directory: /home/me/.cache/action-run/logs

  RUN                               LOG                          SIZE  AGE
  20261021-121355-6ad8e4c30f83      job-1-test_n_one.log        1.2 KB  2 hours ago
  20261021-121355-6ad8e4c30f83      job-2-test_n_two.log        0.8 KB  2 hours ago
  20261020-091201-1f4b2c3d4e5f      job-1-test_n_one.log        1.0 KB  1 day ago

3 logs, 3.0 KB on disk.

--parallel=off goes back to one job at a time, which is what to use when jobs compete for something a unit of concurrency cannot see, such as a fixed port.

7. Know what the run kept

action-run cache

Cache file: /home/me/.cache/action-run/cache.json

  IMAGE                                  SIZE  LAST USED          AGE
  alpine:3.20                         11.8 MB  2026-10-21 15:04  2 minutes ago
  perl:5.38                          157.2 MB  2026-10-21 15:04  2 minutes ago

2 images, 169.0 MB on disk.

Images a run pulled are kept, so the next run starts warm. When they are no longer wanted, action-run cache --prune removes them; --older-than 30d narrows that to the ones at least that old. --no-keep-images makes a single run remove what it pulled.

8. Ask before you push

action-run preflight .github/workflows/ci.yml .

preflight makes the checks a run makes and prepares every image the selected jobs need, then stops. Nothing is started, so it is the cheap way to ask whether a workflow could start on this host — and a mistyped image is caught here rather than halfway through a job.
