   29: =head1 NAME
   30: 
   31: App::Actions::Docker::Variable - an environment variable for a container, kept off the command line
   32: 
   33: =head1 SYNOPSIS
   34: 
   35: Pass a variable to a container:
   36: 
   37: 	use App::Actions::Docker;
   38: 	use App::Actions::Docker::Variable;
   39: 
   40: 	my $docker = App::Actions::Docker->new;
   41: 	my $token  = App::Actions::Docker::Variable->new('TOKEN', $secret);
   42: 
   43: 	# The client is started as "docker run --rm -e TOKEN alpine env", and
   44: 	# TOKEN is set in its environment only.
   45: 	$docker->run('run', '--rm', '-e', $token, 'alpine', 'env');
   46: 
   47: Read its parts:
   48: 
   49: 	print $token->name, "\n";     # TOKEN
   50: 	print $token->value, "\n";    # the secret
   51: 
   52: Print it, for a log (redact secrets first):
   53: 
   54: 	print "$token\n";             # TOKEN=the secret
   55: 
   56: =head1 DESCRIPTION
   57: 
   58: A program's command line is public.  Every user of the computer can read it,
   59: for example with C<ps> or from F</proc/PID/cmdline>.  So a command like
   60: C<docker run -e TOKEN=s3cret ...> shows the secret to everybody.
   61: 
   62: A program's environment is private.  Only the same user (and root) can read
   63: it.  The docker client accepts C<-e TOKEN> with no value: it then copies the
   64: value from its own environment.
   65: 
   66: This class is how a job variable says "give me to docker in the private
   67: way".  Put one after C<-e> in the arguments of an L<App::Actions::Docker>
   68: method.  When the command runs, L<App::Actions::Docker> replaces it with the
   69: bare name and puts the value in the client's environment for that one
   70: command.  See L<App::Actions::Docker/Job variables> for the cases where the
   71: variable must stay on the command line instead.
   72: 
   73: Everywhere else, the object behaves like the string C<NAME=VALUE>: when you
   74: print it, join it, or compare it with C<eq>.
   75:

  163: =head1 COMMON PITFALLS
  164: 
  165: =over 4
  166: 
  167: =item * B<Printing the object prints the secret.>  C<"$variable"> is
  168: C<NAME=VALUE>.  Pass anything you log through
  169: L<App::Actions::Docker/redact> first.  The Docker object's own verbose and
  170: dry-run output already does this.
  171: 
  172: =item * B<Only App::Actions::Docker hides the value.>  If you pass the object
  173: to C<system> or to another module, it becomes the string C<NAME=VALUE> and is
  174: on the command line again.
  175: 
  176: =item * B<A plain string is never hidden.>  C<'-e', 'TOKEN=s3cret'> is passed
  177: as it is.  Only an object of this class is moved to the environment.
  178: 
  179: =item * B<undef is not kept.>  C<new('X', undef)-E<gt>value> is the empty
  180: string, so a container cannot tell an undefined value from an empty one.
  181: 
  182: =back
  183: 
  184: =head1 ENCODING
  185: 
  186: The name should be ASCII letters, digits, C<_>, C<-> and C<.>, and must
  187: start with a letter or C<_>; any other name stays on the command line.  The value may hold any
  188: text, including non-ASCII characters and emoji, but encode it to bytes (for
  189: example UTF-8 with L<Encode>) before you pass it, because an environment and
  190: a command line hold bytes, not characters.  A value with a NUL character
  191: cannot go in an environment, so it stays on the command line.

  242: =head1 STATE DIAGRAM
  243: 
  244: A variable never changes after it is made.  It has one state, and its only
  245: "transition" is how App::Actions::Docker uses it when a command runs:
  246: 
  247: 	   new($name, $value)
  248: 	          |
  249: 	          v
  250: 	+------------------+
  251: 	|     CREATED      |   name and value fixed for ever;
  252: 	| (immutable)      |   "$v" reads as NAME=VALUE
  253: 	+------------------+
  254: 	          |
  255: 	          | passed after -e to App::Actions::Docker->run/capture
  256: 	          v
  257: 	+------------------+  hideable name?   +-----------------------------+
  258: 	|  CHECKED BY      |-------yes-------->| argv gets "NAME";            |
  259: 	|  _hide_variables |                   | %ENV{NAME} = value while the |
  260: 	+------------------+                   | client runs, then restored   |
  261: 	          |                            +-----------------------------+
  262: 	          no (client variable, bad name,
  263: 	          |   case clash or NUL in value)
  264: 	          v
  265: 	+-----------------------------+
  266: 	| argv gets "NAME=VALUE"      |
  267: 	| (visible to every user)     |
  268: 	+-----------------------------+
