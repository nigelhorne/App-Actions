3# Two hand-maintained agreements are easy to apply in half: the schema version
4# a document in t/fixtures/ declares has to match the module that prints it,
5# and a live test's knobs have to be named by the tests, their whitelist and
6# their documentation.  The suite catches either, but only once it runs,
7# which is this hook's job: refuse the commit rather than let CI find it.
8#
9# A commit is checked as a snapshot: the staged files are written to a
10# temporary directory and the checks run there, so a change that is staged in
11# half is caught even if the working tree beside it looks complete.  The
12# pre-commit mode never reads the working tree.
13#
14# Enable it once per clone with
15#
16#     git config core.hooksPath .githooks
17#
18# and skip it for one commit with "git commit --no-verify".
19#
20# The same checks can be run from the command line without committing:
21#
22#     make check-staged    # against the index
23#     make check-worktree  # against the working tree, unstaged edits included
24#
25# They invoke this hook with --staged and --worktree.  The staged mode reads
26# the same index and writes the same snapshot as the hook, so the two cannot
27# disagree about what is committed; the worktree mode runs both checks in the
28# checkout itself, without changing it.
29# Either target lists every check with what became of it - passed, with its
30# test count, failed, or skipped because nothing staged could change what it
31# reads - so a clean run shows which checks ran.  The commit hook itself says
32# nothing when it passes.
